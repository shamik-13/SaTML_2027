# Reproduction package

Everything in the paper, reproducible end to end. Start with **`paper.ipynb`** — it holds the
narrative and the implementation side by side, and every number and every figure in the paper is
produced in it. The figures are drawn by `lib/figures.py`, which `make_figures.py` wraps to write
the PDFs LaTeX includes (`python make_figures.py [OUTDIR]`; the paper source's
`paper/make_figures_satml.py` is the same wrapper pointed at the paper's `figures/` directory), and
the generated tables are written by `lib/tables.py`, wrapped the same way by `make_tables.py`
(`python make_tables.py [OUTDIR]`; `paper/make_appendix_tables.py` is that wrapper pointed at the
paper's `tables/` directory). One implementation each, so the notebook, the artifact and the paper
cannot disagree about what a figure or a table shows.

## Quick start

```bash
pip install -r requirements.txt   # pinned; see the file for what each pin protects
jupyter notebook paper.ipynb      # MODE = "paper", runs in about half a minute
```

To run it headlessly instead (no browser, and all `requirements.txt` needs):

```bash
python -c "import nbformat; from nbclient import NotebookClient; \
  nb = nbformat.read('paper.ipynb', as_version=4); \
  NotebookClient(nb, kernel_name='python3').execute()"
```

The pins matter for one reason in particular: `MODE="full"` refits a
`HistGradientBoostingClassifier`, and a different scikit-learn version can move the scores, hence
the conformal ranks, hence which episodes are detected. `requirements.txt` records exactly what was
verified at these versions and what was not.

The notebook ships with its outputs, so it can be read straight through without executing
anything.

## Two modes

`MODE` is set in the notebook's first code cell.

| MODE | what it does | needs | time |
|---|---|---|---|
| `"paper"` | loads the shipped results in `lib/out/` | nothing | about half a minute |
| `"full"` | recomputes every result from LSPR23 | the dataset, ~27 GB free | ~2-3 h |

Both produce identical output. The shipped artifacts were generated by `MODE="full"` on a
cache rebuilt from scratch, so `"paper"` is a convenience rather than a different answer.

**The theory needs no data in either mode.** Section 1 of the notebook verifies every closed
form the paper states — the feasibility theorem, the padding impossibility, the front-load
bound, the contamination channels, the tie-block algebra, the unit recovery — in about a
minute, with nothing downloaded. A reader can check the theoretical contribution before
deciding whether to fetch 10 GB.

## Getting the data (only for `MODE="full"`)

Both datasets are third-party and neither is redistributed here. See `data/README.md` for the
downloads, the two `awk` recipes that derive the LSPR23 inputs, and the AIT-LDSv2.0 inputs of the
transfer test (one netflow zip per organisation, extracted by `lib/t51_R7_ait.py`). In outline:

1. Download `ls23pr_v1.csv` (10.6 GB) from the LSPR23 Zenodo record.
2. Run the two recipes to produce the feature and port files.
3. For the AIT transfer test, fetch the eight netflow zips (Zenodo 5789064) into `data/ait/`,
   or point `AIT_ZIP_DIR` at them.
4. Set `MODE = "full"` and run the notebook. The flow cache is built on first use (~1 min)
   and reused afterwards.

The cache rebuild is deterministic: rebuilding from scratch reproduces the shipped results
byte for byte.

## Layout

```
paper.ipynb      the paper's implementation, with prose
runner.py        the same stages without the narrative, for batch runs
make_tables.py   the same for the generated tables (lib/tables.py)
lib/             one script per result, each exposing main()
lib/figures.py   every figure; lib/tables.py every generated table, both read lib/out only
lib/out/         the shipped results, one JSON per stage
lib/data/        red-team attack narratives (used by the forensics sections)
data/README.md   how to obtain LSPR23 and AIT-LDSv2.0
data/ait/        the AIT extraction recipe and label mapping (not the data itself)
```

`runner.py` is an alternative entry point for running everything headless:

```bash
python runner.py --theory     # the no-data stages, ~1 min
python runner.py              # everything, ~2-3 h
python runner.py --list       # the stage list
```

## Runtime

Most stages take one to five minutes; the cost is dominated by detector fits over a
16.4M-flow stream. Two stages are slow: the smoothing experiment (~63 min, 100 randomisation
draws per configuration) and the contamination sweep (~20 min, 400 draws per level).

Padding costs are priced by `t28b_reallevel_padding` against the *running* e-LOND level
`1/alpha_t` at each detected episode's step; the same stage also reports the static first-step
threshold `T/w0` (an attacker who suppresses from the first alert, holding the controller at zero
rejections) as the R=0 lower bound. Table I and the padding figures use the running-level costs.

## Notes

- Results are deterministic given the seeds fixed in each script. Detector seeds 0 and 1 are
  reported throughout; where a result depends on randomisation the notebook shows the spread
  rather than a single draw.
- Episode counts, calibration sizes and margins depend only on the stream and the grouping,
  not on the detector, so they are identical across seeds by construction.
- The scripts write to `lib/out/`. Re-running overwrites; move the directory aside first if
  you want to compare against the shipped artifacts.
